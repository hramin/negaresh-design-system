### Deviations and notes

- Small buttons and toggle buttons are 40 px tall with an invisible 44 px hit area (`::after`), so the reference's `btn--sm` look and the 44 px rule both hold.
- Hover, pressed and focus-visible are captured by real pointer and keyboard interaction in the visual tests (desktop); the galleries show the states that props can set (default, disabled, pending, selected, sizes, variants).
- The reference comparison pins each region to the same whole-pixel position before capture, because the content above the footers (fields, alerts) is not built yet and would otherwise shift them by a sub-pixel.
- Menus rely on React Aria's placement defaults (`bottom start`, submenus `end top` = left in RTL). An explicit placement had pushed submenus below their item; the visual test caught it.
- New guard: the smoke test fails if any page scrolls horizontally (it caught the menu page at 390 px).
- `ThemeProvider` sets `data-density` on `<html>`; no component reads it yet (compact tables arrive in P4).
- `Button`'s label wrapper is `display: contents`, so text lays out exactly like a bare label (reference parity) and pending can still hide it.
- `@negaresh/react` builds with Vite library mode (preserved modules); `dist/styles.css` is 3.6 KB gzip (budget 40 KB for all Core CSS).
- Manual checks from `quality.md` (NVDA, VoiceOver, TalkBack, Windows high contrast) were not run in this environment; keyboard behaviour is covered by unit tests (Tab, arrow keys in RTL, Enter/Space, Escape) and the visual focus-visible snapshots.
